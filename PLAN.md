# gnome-workspace-branch — план

Реализованный набор фич, архитектура, биндинги и сборка описаны в [README.md](README.md). Здесь — только **открытые проблемы** и **отложенные задачи**.

---

## Известные баги

### 1. Autostart открывает лишние окна

**Симптом:** при включении расширения / старте сессии VS Code открывает несколько пустых окон, Helium открывает вторую копию, Telegram дублируется.

**Причина:** в `tryLaunch` после `app.activate()` была синхронная проверка `stillSameAfter`, которая всегда срабатывала (окно ещё не успевало появиться, т.к. activate асинхронный) → фоллбек `spawnFromDesktop` лупил `/usr/bin/code`/`Telegram --` поверх activate'а.

**Фикс:** убран синхронный fallback (`32316ff`). Сейчас только `Shell.App.activate()`. Маркер сессии в `$XDG_RUNTIME_DIR` гарантирует один запуск.

**Статус:** требуется logout/login для проверки (GJS кэширует модули — `disable+enable` не подхватывает изменения в `lib/*.js`).

### 2. Stack-режим ломается после drum rotation

**Симптом:** когда в колонке N окон стека и пользователь крутил барабан, открытие N+1-го окна создаёт **2-3 пустых воркспейса** между текущим максимумом и новым окном.

**Причина:** старый `tryApply` считал target layer как `base + countAppWindows`. После rotateColumn абсолютные номера слоёв сдвигаются (`L=-1,0,1,2` вместо `L=0,1,2,3`), но `count=4` оставался → `target=L4` → loop в `resolveTargetIdx` создавал `L=3` и `L=4`, оставляя `L=3` пустым.

**Фикс:** `nextStackLayer` ищет максимальный занятый слой колонки в направлении стека (по `topology.positionOf` + `Shell.WindowTracker`) и берёт следующий за ним. Устойчиво к ротации.

**Статус:** код в `lib/window-rules.js`, нужен `make install` + relogin.

### 3. Артефакты отрисовки при переключении

**Симптом:** при стандартном перемещении воркспейса (особенно двойной свайп подряд) изображение не сразу прорисовывается — нужно переключиться туда-обратно. Новые окна тоже иногда требуют пары переключений, чтобы появиться.

**Гипотеза:** скорее всего связано с `_workspacesAdjustment` linear lerp (тот самый «кратковременный диагональный slide» из README) или с `VerticalMonitorGroup` allocate, который не всегда успевает на быстрых последовательных свайпах.

**Статус:** требуется repro с логами после relogin. Возможно, частично уйдёт после фикса №2 (меньше призрачных воркспейсов = меньше путаницы у анимации).

### 4. Внешние workspace-added события

**Симптом:** иногда воркспейс/окно создаются «не нами» (например, окно открывается без правила в неожиданное место), и плагин этого не отслеживает корректно — например, барабан считает, что окно не открывалось.

**Гипотеза:** `topology.onWorkspaceAdded` всегда трактует неучтённое добавление как расширение main row. Если что-то добавило ws в конец линейного списка как «отросток без регистрации», топология этого не понимает.

**Статус:** нужен concrete repro с журнальными логами `workspace-added/removed` чтобы понять, откуда в действительности приходят добавления. Возможно, это побочка фикса №1 — лишние autostart-окна → лишние `display::window-created` → лишние `_ops.create` без полного завершения предыдущего.

## Отложенные задачи

### Profiles (Фаза 6)

Заготовки в `lib/profiles.js` и `lib/profile-switcher.js`, схема ключи `profiles` + `active-profile` сохранены, но UI убран и инсталляция отключена в `extension.js`. Возврат — после стабилизации per-rule autostart.

### Variant B для left/right в отростке

Сейчас left/right в отростке снапает на main соседней колонки (Variant A). Variant B = переход в отросток того же слоя соседней колонки если он есть. Можно сделать настройкой.

### Drum auto-create

Сейчас drum работает только если в колонке уже есть слой в нужном направлении. Возможный UX: «первое нажатие Super+Up на колонке без отростков → создаёт его и сразу крутит».

### Overview vertical clamp

Если отростков много, thumbnails главного ряда ужимаются по вертикали. Нужен max видимых на колонку (скролл? clamp?).

### Layout preview: live windows

Сейчас в prefs preview показывает только иконки правил. Можно добавить превью реальных окон, которые сейчас лежат на (col, layer).

### Drop-catcher выше/ниже thumbnail-strip в overview

Из «Limitations» в README: DnD в column-up/down zone работает только над уже существующими thumbnails. Дроп выше/ниже самой полосы требует отдельного drop-catcher актора.

### `_workspacesAdjustment` для далёких отростков

Из «Limitations»: linear lerp progress между далёкими отростками иногда даёт диагональный slide через промежуточные индексы. Лечится либо custom progress curve, либо снапом сразу к target без промежуточных кадров.

## Стратегические заметки

- **Static workspaces форсятся в `enable()`** (`mutter.dynamic-workspaces = false`), иначе Mutter сам добавляет/удаляет последний пустой и наша топология рассинхронизируется. На `disable()` возвращаем исходное значение.
- **`Main.wm.insertWorkspace` no-op в static-режиме** — используем `workspace_manager.append_new_workspace` + `reorder_workspace` напрямую везде, где нужно вставить в середину линейного списка.
- **GJS кэш ES-модулей** переживает `gnome-extensions disable && enable` — для проверки изменений в `lib/*.js` нужен полный рестарт shell (logout/login на Wayland). Settings-изменения подхватываются на лету.
- **Tray-only приложения** (Telegram с `-autostart`): `Shell.App.activate()` не может вытащить окно из приватного трея — нужно отключать tray-on-start в самом приложении.
- **AMW совместимость**: индексы 1..N main row не трогаем; AMW и наши правила могут сосуществовать без миграции конфига.
